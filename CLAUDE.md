# closet-ai: notes for Claude Code

## What this is

A wardrobe app, mobile-first. You photograph an item and the app tells you what to wear it with, or helps you sell it. Everything you photograph ends up in your digital wardrobe, so it fills up as a side effect instead of a chore.

The core feature is "Want / Can": the user drops in a screenshot of something they want, and the app shows how to (1) build a similar look from their own wardrobe, (2) find something similar for less, (3) sell items they don't wear to afford it.

First market is Israel (Hebrew + Russian, Yad2 and Facebook groups), then Ukraine and Belarus. Free tier forever, 7-day Pro trial, then subscription via RevenueCat. Stylists will later get access to clients' wardrobes, so sharing is part of the data model from the start. See README.md for the full roadmap.

This is also a learning project. The owner is a frontend engineer (React, React Native) building her backend, TypeScript and AI skills on it, and it is part of her portfolio.

## Current state

- pnpm monorepo (`client`, `server`, `shared`), TypeScript ~6.0 strict everywhere (keep one TypeScript version: two versions make pnpm install `expo` twice), Node 22. pnpm may not be on PATH: use `corepack enable` once, or `corepack pnpm …`.
- `server/` (`@closet-ai/server`): Fastify 5 + Zod (`fastify-type-provider-zod`), Drizzle ORM 0.45 on Postgres 17 with pgvector, health check.
  - Auth: Better Auth (email + password) on `/api/auth/*`, Expo plugin, trusted origin `closetai://` (plus `exp://` in development). Its tables (`user`, `session`, `account`, `verification`) are generated by the Better Auth CLI into `src/db/auth-schema.ts`; don't edit that file by hand.
  - Items: `GET/POST /api/items` require a session (`requireUser` preHandler, 401 otherwise) and only touch the caller's items (`items.owner_id` → `user.id`).
  - `buildApp` takes auth and the repository as parameters, so tests use Better Auth's in-memory adapter and an in-memory repo and need no database. `disableOriginCheck: false` is set on purpose: Better Auth skips the origin check when NODE_ENV is test.
  - Migrations are committed in `server/drizzle/`.
- `shared/` (`@closet-ai/shared`): Zod schemas and types for server and client. Exported as raw TS (`exports: ./src/index.ts`), no build step.
- `client/` (`@closet-ai/client`): Expo SDK 57, Expo Router (`src/app`), TypeScript. On 57, not 58, until Expo Go for SDK 58 reaches the App Store (Expo said "within a few weeks" of the October 2026 release); then upgrade with the `expo-upgrade` skill and unpin `test-renderer`. Signed-in screens are tabs in `src/app/(tabs)` (JS `Tabs`, not NativeTabs, so the bar can use our fonts and icons): Home, Closet, Want, Trends, Profile. Profile is the menu (`src/screens/menu`); Closet is a placeholder list of categories from `@closet-ai/shared`; the rest render `ComingSoon`. Menu sections that aren't built yet are disabled with a "soon" tag. Icons: stroke paths from the design in `src/components/icon.tsx` (`react-native-svg`). i18n: i18next + react-i18next in `src/i18n`, languages en (fallback), he, ru, picked from the device via `expo-localization`; `t()` keys are typed from `en.json`. Auth: Better Auth client with the Expo plugin (`src/lib/auth-client.ts`), session cookie in `expo-secure-store`, sign-in / sign-up screens behind `Stack.Protected` in `src/app/_layout.tsx`. Look: the "powder" design (canvas https://claude.ai/artifact/2Ei1E9R3sAHNcqvCJ1TSXN); colors and font names in `src/theme.ts`, fonts (Cormorant Garamond, Manrope from `@expo-google-fonts`) loaded with `useFonts` in `_layout.tsx`. Use `colors` / `fonts` from the theme instead of raw hex values, and a font family per weight instead of `fontWeight`. API URL: `EXPO_PUBLIC_API_URL`, or in development the LAN host Metro serves from, port 3000. Tests: Jest 29 + jest-expo + Testing Library (`pnpm --filter @closet-ai/client test`). `test-renderer` is pinned to ~1.2 because 1.3 needs React 19.3 and SDK 57 ships React 19.2.
- No `node-linker=hoisted`: Expo supports pnpm isolated installs since SDK 54. Switch to `nodeLinker: hoisted` in `pnpm-workspace.yaml` only if a native library breaks.
- `docker-compose.yml`: Postgres 17 + pgvector and Redis, published on 127.0.0.1 only. `docker/postgres/init.sql` creates `closet_test` when the volume is first created (`docker compose down -v` to recreate). On the owner's Mac Docker runs in OrbStack.
- Lint: ESLint 9 (not 10: `eslint-plugin-react` inside `eslint-config-expo` crashes on 10). Root `eslint.config.js` covers `server` and `shared` with type-aware `typescript-eslint` rules; `client/eslint.config.js` uses `eslint-config-expo`, which includes the React Compiler rules. `pnpm lint` runs both and fails on warnings.
- CI: `pnpm install --frozen-lockfile`, typecheck (all three packages), lint, tests, with a Postgres 17 + pgvector service for the server's Postgres tests. Commit `pnpm-lock.yaml` together with any `package.json` change.

## Tests

Tests stay inside each package, not in a shared top-level folder:

- `server/test/` for API tests (Vitest). Unit tests for a single module can also sit next to it as `*.test.ts`.
  - `server/test/postgres.test.ts` runs the real app (Drizzle repository, Better Auth Drizzle adapter, committed migrations) on Postgres. It runs only when `TEST_DATABASE_URL` is set, always in CI (a Postgres service in the workflow), and fails in CI if the variable is missing. It wipes that database first, so the database name must end in `_test`. Locally (`pnpm db:up` creates `closet_test`): `TEST_DATABASE_URL=postgres://closet:closet@localhost:5432/closet_test pnpm --filter @closet-ai/server test`.
- `client/` uses Jest (jest-expo), with tests next to components as `*.test.tsx`. Never put tests in `src/app`: every file there becomes a route.
- `shared/` gets Vitest only when there's real logic there; plain schemas don't need tests.

Reason: server and client use different test runners and environments (Node vs React Native), and each package should be testable on its own with `pnpm --filter <pkg> test`. If we add end-to-end tests later, they go in a top-level `e2e/`.

## RTL

- RTL is enabled with `supportsRTL: true` in the `expo-localization` plugin (`app.json`); on iOS it only applies to locales listed in `supportedLocales` (en, he, ru).
- Use `start`/`end` (`marginStart`, `paddingEnd`, …) instead of `left`/`right` in styles.
- `textAlign` has no `start`/`end` in React Native: `'left'` follows the layout direction and acts as start.
- Changing direction at runtime (`I18nManager`) needs an app restart and does not work in Expo Go.

## Conventions

- Zod schema in `shared` is the single source of truth: TS types, request validation and DB enums come from it.
- AI calls go through one client module in `server` so tests can swap it for a stub and never spend money.
- Secrets only in `.env`, never committed. `.env.example` is kept up to date.
- UI strings go through i18n from the start (en as fallback, he, ru; uk later). No hardcoded text in components. New strings go into `en.json` first; a test checks that he and ru have the same keys.

## Commands

```bash
pnpm install
pnpm db:up                                    # Postgres + Redis in Docker
cp server/.env.example server/.env              # then set BETTER_AUTH_SECRET: openssl rand -base64 32
pnpm --filter @closet-ai/server db:migrate     # apply committed migrations
pnpm --filter @closet-ai/server db:generate    # only after changing src/db/schema.ts; commit the result
pnpm dev:server                               # API on http://localhost:3000
pnpm dev:client                               # Expo dev server
pnpm typecheck
pnpm lint
pnpm test
```
