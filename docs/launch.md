# Запуск для тестеров

Чек-лист владелицы. Порядок важен: сначала сервер, потом сборка, потому что адрес API зашивается в сборку. Цены и правила Apple проверяй на их страницах: здесь они могут устареть.

## 1. Аккаунты и покупки

- [ ] **Домен**: любой дешёвый нейтральный. API будет на `api.<домен>`.
- [ ] **VPS Hetzner Cloud**, Германия или Финляндия, Ubuntu LTS, 2 vCPU и 4 ГБ памяти (API и воркер вместе занимают около 1 ГБ). При нехватке тариф меняется в пару кликов.
- [ ] **Cloudflare R2**: два приватных bucket, `closet-photos` и `closet-backups`, и API-токен только на них. Запиши Account ID, Access Key и Secret.
- [ ] **Ключи AI**: Anthropic и fal. Поставь лимит расходов в кабинете каждого сервиса.
- [ ] **Почта поддержки**: для политики и кнопки «Сообщить о проблеме».

## 2. Сервер

Сначала слей PR с деплоем в `main`. Затем:

1. В DNS добавь A-запись `api` с IP сервера.
2. Зайди на сервер по SSH-ключу. Открой в firewall только порты 22, 80 и 443. Создай пользователя `deploy` и поставь Docker по инструкции docs.docker.com.
3. Настрой сервер:

```bash
git clone https://github.com/AStashevskaya/closet-ai.git && cd closet-ai/deploy
cp .env.example .env
openssl rand -hex 32      # в POSTGRES_PASSWORD
openssl rand -base64 32   # в BETTER_AUTH_SECRET
nano .env                 # заполни остальное, API_DOMAIN=api.<домен>
docker compose up -d --build
curl https://api.<домен>/health   # ответ: {"status":"ok"}
```

Если репозиторий приватный, для `git clone` нужен deploy key из настроек GitHub.

4. Загрузи демо-каталог: `docker compose exec api node_modules/.bin/tsx src/scripts/import-catalog.ts`.
5. Включи бэкапы: `crontab -e`, строка есть в начале `deploy/backup.sh`. Запусти скрипт вручную один раз и проверь, что файл появился в R2.
6. **Проверь восстановление**: разверни дамп в отдельной базе на сервере. Непроверенный бэкап не считается.

Обновление сервера: `git pull && docker compose up -d --build`. Миграции применятся сами до старта нового кода.

Откат: `git checkout <прошлый коммит> && docker compose up -d --build`. Миграции назад не откатываются, поэтому перед рискованным обновлением делай бэкап.

## 3. Первая сборка, только для тебя

На Mac, из папки `client/`:

```bash
eas login
eas init                  # создаст проект EAS и допишет projectId в app.json: закоммить это
eas env:create --environment preview --name EXPO_PUBLIC_API_URL --value https://api.<домен> --visibility plaintext
eas env:create --environment preview --name EXPO_PUBLIC_SUPPORT_EMAIL --value <почта> --visibility plaintext
eas build --platform ios --profile testflight   # спросит вход в Apple и сам создаст сертификаты
eas submit --platform ios --profile testflight --latest
```

Сборка идёт в облаке EAS и занимает примерно 20–40 минут. Обработка в App Store Connect занимает ещё немного времени.

- [ ] Если при `eas submit` имя занято, задай в App Store Connect другое, например `Closet Wardrobe Beta`. Имя под иконкой от этого не зависит.
- [ ] В TestFlight добавь себя как внутреннего тестера и поставь приложение на телефон.

**Проверь на телефоне:** регистрация и вход; одна вещь и пачка фото; вырезание вещи; образ из селфи; Recreate; Style it; Inspiration; Wishes; удаление аккаунта; авиарежим при первом открытии вкладки; бирка в движении; иврит с RTL; русский с длинными строками; запрет доступа к камере.

## 4. Перед приглашением тестеров

- [ ] Заменить иконку и экран запуска, если там ещё шаблон Expo.
- [ ] Запустить `senior-qa`, `/closet-security-review`, `/closet-release-check` и `/closet-ai-cost`.
- [ ] Заполнить `docs/legal/privacy-policy.md`: имя, страна, почта, дата и хостинг (Hetzner, регион). Опубликовать на открытой странице, например в Notion.
- [ ] **Согласие в приложении: нужно решение.** Сейчас в приложении нет ни ссылки на политику, ни согласия на передачу данных за границу. Без них реальных людей не приглашаем.
- [ ] Вписать id тестеров в `TESTER_USER_IDS`, если им нужны лимиты шире.

## 5. Внешние тестеры

В App Store Connect → TestFlight:

1. Заполни описание бета-версии, почту для обратной связи и ссылку на политику конфиденциальности.
2. Создай группу внешних тестеров и добавь сборку. Первая сборка проходит Beta App Review, поэтому дай Apple тестовый аккаунт: почту и пароль, заранее заполненный гардероб.
3. После одобрения включи публичную ссылку или пригласи тестеров по почте. Им понадобится приложение TestFlight.

**Новая сборка:** снова `eas build` и `eas submit`, номер сборки вырастет сам. TestFlight-сборка живёт 90 дней. OTA-обновлений пока нет: любое изменение клиента требует новой сборки.

**Первая неделя:** смотри `docker compose logs -f api worker`, расходы AI и место на диске (`df -h`). Отчётов о падениях пока нет (Sentry запланирован), поэтому проси тестеров присылать скриншоты.
